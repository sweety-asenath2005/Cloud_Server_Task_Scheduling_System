Cloud Scheduling Strategies

Learn how each scheduling strategy decides which cloud task gets CPU execution next.

1. FCFS — First Come First Serve

Cloud Context: When cloud tasks arrive at the server, they are handled in their arrival order.

How It Works

  • Cloud tasks are sorted by their arrival time.
  • The server CPU executes each task fully, one after another, in that order.
  • If no cloud task has arrived, the server CPU stays idle until the next arrival.

Advantages

  • Simple to understand and implement.
  • Fair in terms of arrival order — no cloud task starves.

Disadvantages

  • Short cloud tasks can wait behind long ones (convoy effect).
  • Not ideal for time-sharing cloud workloads.
Example: T1 (AT 0, CPU 5), T2 (AT 1, CPU 3) → T1 runs first (0–5), then T2 (5–8), even though T2 arrived early and is shorter.

2. SJF — Shortest Job First (Non-Preemptive)

Cloud Context: The scheduler selects the available cloud task requiring the shortest CPU execution time.

How It Works

  • At every decision point, look at all cloud tasks that have arrived but not yet executed.
  • Pick the one with the shortest CPU execution time and run it to completion.
  • If nothing has arrived yet, the server CPU stays idle.

Advantages

  • Minimizes average waiting time among non-preemptive strategies.
  • Efficient for batch cloud workloads with known CPU times.

Disadvantages

  • Requires knowing CPU times in advance, which is often unrealistic.
  • Long cloud tasks may face starvation if short tasks keep arriving.
Example: T1 (AT 0, CPU 5), T2 (AT 1, CPU 3) → T1 starts at 0 since it's the only task available; once T2 has arrived, it still must wait for T1 to finish because SJF here is non-preemptive.

3. Priority Scheduling (Non-Preemptive)

Cloud Context: The scheduler gives CPU access to the highest-priority available cloud task.

How It Works

  • Only cloud tasks that have already arrived are considered.
  • The task with the smallest priority number is selected first (lower number = higher priority).
  • Ties are broken using arrival time, then original input order.

Advantages

  • Important or urgent cloud tasks can be completed sooner.
  • Flexible — priority can represent deadline or importance.

Disadvantages

  • Low-priority cloud tasks may starve if high-priority tasks keep arriving.
  • Choosing a fair priority value can be difficult.
Example: T1 (Priority 2), T2 (Priority 1) → T2 runs before T1 because a lower number means higher priority.

4. Round Robin

Cloud Context: The scheduler gives each cloud task a limited CPU time and cycles through the task queue.

How It Works

  • Cloud tasks are placed in a ready queue as they arrive.
  • The server CPU executes the first task for one time quantum, or until it finishes — whichever is smaller.
  • If the task still needs more time, it goes to the back of the queue.
  • Newly arrived tasks join the queue and this cycle continues until every task is done.

Advantages

  • Fair CPU distribution — good for time-sharing cloud systems.
  • No cloud task waits too long before getting some CPU time.

Disadvantages

  • Performance heavily depends on choosing a good time quantum.
  • Too small a quantum increases overhead; too large behaves like FCFS.
Example: Time Quantum = 2. T1 (CPU 5) runs 0–2, then T2 gets a turn, and T1 returns to the queue for its remaining 3 units.
